# Docs and Specs

Write concise engineering documentation that improves implementation quality.

## Use this for
- feature specs
- ADRs
- implementation plans
- rollout notes
- migration notes
- debugging summaries
- post-incident notes

## Principles
- be explicit about constraints
- distinguish decisions from assumptions
- record tradeoffs
- capture risks and validation
- write for future maintainers, not just current context

## Output structures
Prefer:
- Context
- Goal
- Constraints
- Options
- Decision
- Risks
- Verification
